# UnifiedLM 的核心研究目标

依据用户于2026-10-22的澄清，本文确定项目的主线。快慢记忆是候选机制之一，不是项目的首要研究命题。

## 出发点

1. Attention 是可微分的检索与信息聚合机制。
2. FFN 可以视为参数化 KV memory：key 和 value 存在权重矩阵中，激活／门控执行寻址和特征选择。
3. 动态上下文和静态参数知识既然都能表示为 KV，值得寻找一种共同的计算原语来处理二者。
4. 目标是在整个模型中，以同一种核心操作承担知识存储、信息检索与特征变换，从而统一 token mixer 和 channel mixer 的形式及实际执行。

## 核心主张与边界

“统一”需要落实到具体的地址函数、读出规则、状态布局和执行数据流。将两类 mixer 分别写成 KV 形式，只建立了共同表示；将不同计算封装成一个 block，也不足以证明统一机制成立。

当前 UnifiedLM 是一个候选：同一个槽读取形式同时访问参数知识与序列相关状态。必须继续检查其中的共享约束是否有用、静态和动态计算能否由相同执行单元承载，以及投影、归一化、更新等辅助计算的完整成本。

同一数学形式可以有多种实现。并行训练的等价分解不自动否定统一；也不能仅凭统一形式推导GPU速度提升。硬件收益需要由具体的融合、矩阵形状、批处理、状态读写、访存及调度证明。

## 相关扩展的位置

- 权重本身作为可寻址、可读取、可能在线修改的 memory，是统一原语的一条实现路径。
- 快慢记忆与 TTT 描述存储及更新方式；其价值要结合统一 token/channel mixing 的主张判断。
- 循环通过复用同一算子增强变换能力，应明确每轮查询与状态如何变化，以及新增计算的有效性。
- 生物合理性、FPGA、有限fan-in及低位宽提供设计启发与工程方向，不替代语言建模与统一机制的验证。

## 主要验证问题

1. 同一个明确、可执行的原语能否同时承担跨token信息传递和token内部的非线性特征变换？
2. 这种统一能否达到同规模llama2.c的语言建模质量？同训练token预算与同计算／时间预算分别报告。
3. 共享地址、状态表示和计算规则，相对分离的token/channel mixer有哪些质量、参数、执行与存储收益或代价？
4. 统一后的数据流是否在真实GPU实现中改善吞吐、访存或调度？其后再检验FPGA上的资源及通信收益。
5. 新颖性应与已经统一attention和FFN形式的工作直接比较，准确界定新的算子、约束、实现或实证贡献。

快记忆消融检验机制贡献，不能独立证明统一计算原语的价值。语言模型loss下降检验可训练性，也不能独立证明硬件效率或创新性。

## 当前执行状态

原版UnifiedLM完整260K训练继续作为基线证据。以快慢路径为中心的独立变体保持草稿状态，尚未启动训练；后续方案依照上述目标筛选。
