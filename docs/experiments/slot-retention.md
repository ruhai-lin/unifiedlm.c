# 每個格子記多久（按寫入量加權）

**問題**：遺忘門的“有效記憶長度”只有 1–2 個 token，記憶真的這麼短嗎？

**簡短回答**：不是：按寫入量加權，U-Delta-rawFFN+λlr1000 有 3 層（42M 有 5 層）過了 256 個 token 還留 20–50%；U-Delta-λlr1000 也有 4 層。

## 怎麼做的

- 每層每個格子 a：第 s 步寫進去的內容，過了 D 個 token 只靠衰減還剩 ∏_{s<t≤s+D} λ_{t,a}；按寫入量 β_s k_{s,a}² 加權平均，D = 16、64、256（`scripts/fineweb/slotlen.py`，32 個窗口）。
- 跟 `gates.py` 的“有效記憶長度”不同：那個是按格子、按 token 平均的遺忘率，被大量的快格子主導；這裡看的是寫進去的東西實際遇到的衰減。
- 只算衰減，不算之後寫入造成的覆寫（覆寫見[遺忘還是覆寫](forgetting-vs-overwrite.md)）。

## 結論

- **按格子平均的記憶長度會被快格子拉低**：UD2 15M 第 9、10 層的有效記憶長度只有 1.1、1.6 個 token，按寫入量加權過了 256 個 token 還留 16%、20%；第 1 層 628/712 個格子過了 256 還留超過 1/e，整層留 36%。之前說“記憶幾乎被關掉”是看錯了指標。
- **模型自己分工：少數層慢、其他層快**：U-Delta-rawFFN+λlr1000 15M 第 1、2、10 層過了 256 個 token 還留 20–44%，其他層最多 5%；42M 第 2、3、8、12、15 層留 22–50%（第 3 層 1,171/1,248 個格子），其他層最多 13%。
- **遺忘率學快以後，慢的層變少，但沒有消失**：U-Delta 15M 有 5 層留 35–51%（第 1、2、3、4、11 層），U-Delta-rawFFN+λlr1000 15M 剩 3 層；42M 的 U-Delta-rawFFN 有 12 層留 23–90%，U-Delta-rawFFN+λlr1000 剩 5 層。
- **U-Delta-λlr100、λlr1000 也是少數層慢**：λlr1000 第 1、2、3、11 層過了 256 個 token 還留 34/18/19/21%，第 4–10 層 0%；λlr100 第 1、2、3、11 層留 48/31/24/30%，其他層最多 8%。之前說它們“幾乎每層都忘到上限”只對中間幾層成立。
- **加讀出門，慢的層變多**：UD2-gate 第 1、3、8、9、10、11 層過了 256 個 token 還留 51/19/13/53/27/41%；沒有門的 UD2 只有第 1、9、10 層（36/16/20%）。
- **讀出端的修改會換掉記得久的層**：UD2-gate-norm 第 0、2、4、8、9、10 層過了 256 個 token 還留 39/11/23/45/58/16%（UD2-gate 記最久的第 1 層只剩 1%）；UD2-gate-q32 第 1、2、7、8、10、11 層留 42/38/43/21/14/41%；兩個一起的 UD2-gate-norm-q32 第 0、6、8、9、10、11 層留 35/12/32/42/29/26%；UD2-scale 跟 UD2 一樣只有第 1、8 層（36/22%）。
- 有幾層只有少數格子記得久，卻接走了大部分寫入：U-Delta-rawFFN 42M 第 6 層只有 7 個格子過了 256 還留超過 1/e，但整層留 90% 的寫入量。

## 注意

- 只算衰減，沒算覆寫，所以是記憶長度的上限。
- 32 個窗口、各 1 個 seed。
