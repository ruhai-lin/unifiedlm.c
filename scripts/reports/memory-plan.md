# 記憶實驗計畫（2026-11-07，Gary 已確認）

**Gary 的決定（2026-11-07）：** 三項都照建議。只測上下文記憶；對照組是 Transformer 和分開版 P-free；先做合成任務 M1–M3，
結果出來再決定要不要上真實文字。第 6 節是 M1 的固定規則，在任何 M1 結果出來之前寫下。

前提（`checkpoint-2026-11-07.md`）：統一 block 能學，同寬度下每個 token 快 12–19%。Gary 確認速度夠了，下一步看記憶能做到多少。

## 0. 要回答的問題

這裡的「記憶」指 attention 那半：從**前文**記住東西再拿出來用。它的狀態大小固定（每層 d×m），跟文長無關，
這是速度的來源，也是記憶的上限。所以問題是：

1. **容量：** 前文裡放 N 組「鑰匙→值」，之後問鑰匙，它能答對幾組？N 多大開始掉？
2. **距離：** 隔多遠還記得？超過訓練長度還記得嗎？
3. **更新：** 同一把鑰匙後來換了值，它答新的還是舊的？

每一題都跟兩個對照比：

- **Transformer**（同參數）：KV cache 會隨文長變大，記憶幾乎沒有上限，是天花板。
- **分開版 P-free**（同寬度、同狀態大小）：看「位址跟 FFN 共用」會不會傷記憶。這跟速度那一題是同一組對照：
  統一版省了時間，記憶有沒有付出代價。

## 1. 從數學先預測

讀出是每個槽的加權平均：`(w·μ + Σ λ^(t-s) r_{s-1} v_s) / (w + Σ λ^(t-s) r_{s-1})`。

- **容量：** 每層有 m 個槽，鑰匙組數接近 m 之後，不同鑰匙會擠到同一些槽，答案會混在一起。預測掉點的位置跟 m 成比例。
- **更新：** 同一個槽寫兩次，讀到的是兩個值的平均，不是新的那個；λ 接近 1 時（初始化約 0.9995）新舊幾乎一樣重。
  預測 S 在更新題會明顯輸 Transformer。這是「平均式」記憶的結構限制，delta rule 一類的寫法（例如 GDN）沒有這個問題。
- **先驗：** 一個槽的先驗質量 w 初始是 4 個 token，上下文寫一次的權重最多 1/5。模型要學會把當暫存器用的槽的 w 調小。

這些預測先寫下來，實驗結果再對照。

## 2. 第一階段：合成任務（便宜，先做）

不需要下載資料，資料在訓練時隨機生成。模型很小，一個 run 預計幾分鐘到十幾分鐘（先跑一個試點量時間）。

### M1 容量：多組鑰匙查詢（MQAR）

- 序列：N 組隨機「鑰匙 值」，後面接打亂順序的鑰匙，每個鑰匙後面要預測它的值。只在答案位置算 loss 和正確率。
  這是 Zoology（Arora 等，2023）用來比較固定狀態模型記憶的標準任務。
- 詞表 8192，序列長 512（N 組鑰匙和值加上 N 個問題答案共 4N 個 token），N ∈ {8, 16, 32, 64, 128}。
- 寬度 d ∈ {64, 128, 256}；槽數 m 照 `docs/models.md` 的規則讓參數量對齊 Transformer。
- 模型：S、P-free、Transformer（2 層，對應 4 個 UnifiedBlock）。
- 每個（模型、寬度）掃 4 個學習率，取驗證最好的，這是合成任務的標準做法。篩選 1 個 seed，最後的圖 3 個 seed。
- **主圖：** 正確率對「每層狀態大小」，也就是記憶跟推論成本的取捨。

### M2 距離

- 鑰匙在前面、問題在最後，中間塞 G 個無關 token。訓練時 G 最多 256，測試 G 到 4096。
- 看正確率隨 G 怎麼掉，S 和 P-free 的 λ 學成多少。

### M3 更新

- M1 的變形：部分鑰匙會再出現並換成新值，問的是最新的值。
- 預測 S 和 P-free 都會偏向平均值，Transformer 不會。

### 成本和程式

- 新寫 `scripts/memory/`：資料生成、只在答案位置算 loss 的訓練迴圈、一個最小的 Transformer block（llama2.c 形式）。
  S 和 P-free 直接用現有的 `model.py` 和 `scripts/variants.py`。
- 粗估：M1 是 3 模型 × 3 寬度 × 4 學習率 = 36 個篩選 run，加上 seed，約 5–10 卡時；M2、M3 各約一半。
  先跑試點量真實時間再更新。
- 先在本機 CPU 用極小設定確認程式對，再上 NRP（A40，A6000／L40 也已核准）。

## 3. 第二階段：真實文字（第一階段之後再決定）

- 需要長文的資料集（TinyStories 一篇只有幾百個 token，測不出長距離記憶），例如 FineWeb-Edu 或 PG19，模型至少 15M。
- 測：每個位置的 loss 隨文長怎麼變、超過訓練長度後的表現、在長文中藏一段密碼再問（passkey）。
- 成本高一個量級（15M 完整訓練在 3090 Ti 上約 17 小時），所以等合成任務的結果再決定。

## 4. 不在這次範圍

- 權重記憶（FFN 那半能存多少知識）：可以之後用合成的人物資料測「每個參數存幾 bit」。
- 跟 GDN、Mamba2 這類最強的固定狀態模型比：要在 NRP 環境多裝 fla，約多一天工。M3 的預測如果成立，這個比較就很有意義。

## 6. M1 的固定規則（在任何 M1 結果之前寫下）

程式：`scripts/memory/mqar.py`（`--task=m1`）。

- **資料：** 詞表 8192；鑰匙取自 1–4095，同一條序列內不重複；值取自 4096–8191；0 是補位。
  序列長 1024（修正前 512）：N 組「鑰匙 值」，接著 N 個鑰匙以隨機順序再出現、各接一個 0，剩下補 0。

- **評估集固定：** 每個 N 各 1024 條驗證序列、1024 條測試序列，用固定的亂數種子產生，所有模型、所有 run 都一樣。
  驗證集用來選學習率，測試集用來報告。
- **模型：** d ＝ 32、64、128（修正前 64、128、256）。
  - T：2 層 llama2.c 形式（RoPE、SwiGLU、head 維度 32、embedding 和輸出共用）。
  - S：4 個 UnifiedBlock，槽數 m ＝ 83、171、323，讓參數量對齊 T（S 是 T 的 99.97%）。
  - P：P-free，每條路都是 m 個槽，參數比 S 多 4–12%。
- **訓練：** batch 64（修正前 128；序列加倍，每步的 token 數不變）；AdamW（0.9, 0.99），weight decay 0.1（只對 2 維以上的參數）；warmup 500 步後 cosine 降到 0；
  梯度裁切 1.0；bf16 autocast、`torch.compile`。
- **步數：** 先跑試點（`scripts/nrp/mem_pilot.txt`：d＝128、40K 步、每 2K 步評估；S、P 用 lr 1e-3，T 用 3e-4、1e-3、3e-3）。
  如果所有曲線從 20K 步起都平了（各 N 平均正確率跟 40K 時差不到 1 個百分點），M1 用 20K 步，否則用 40K 步。
  試點只用來定步數和量時間，不進比較。
- **T 必須先證明學得會：** 不配對鑰匙、只從前文的值裡隨便挑，正確率是 1/N。試點裡如果三個學習率的 T 在 N≤32
  都沒有到 90% 以上，就停下來查原因、通知 Gary，不開始掃描，因為天花板不成立，比較就沒有意義。
- **Gary 2026-11-07：不掃學習率。** 這是 PoC，每個（模型、寬度）只跑 lr 1e-3、seed 1337 一次（試點裡三種模型用 1e-3 都學會）。
  `mem_m1.txt` 其他 27 行在任何 run 開始前用手動 claim 擋下，沒有跑。下面兩條是原本的規則，留著備查。
- **學習率（原規則，未執行）：** 每個（模型、寬度）掃 3e-4、1e-3、3e-3、1e-2，seed 1337，選各 N 平均驗證正確率最高的。
  差不到 0.5 個百分點時取較小的。最好的落在 1e-2 或 3e-4 時，往那個方向多試一格（3e-2 或 1e-4），只對那一組。
- **報告（原規則，未執行）：** 選定的學習率再跑 3 個 seed（2001、2002、2003），報告測試正確率的平均。
  **Gary 2026-11-07：** 這是 PoC，沒有他同意不跑多 seed。掃描完先報告 1 個 seed 的結果，當作初步觀察，不下判定。
  狀態大小：S 和 P 是 4 × d × m 個數（快記憶）；T 是 KV cache，2 層 × 2 × d × 4N。
- **怎麼判斷「共用位址傷記憶」：** 每個寬度、每個 N，算 S 減 P 的正確率差（現在只有 1 個 seed，結果只算初步觀察）。
  - 所有 N 都差不到 5 個百分點：判定「沒有差別」。
  - 有任何 N 的 S 低 5 個百分點以上：判定「共用傷記憶」。
  - 有任何 N 的 S 高 5 個百分點以上、而且沒有任何 N 低 5 個以上：判定「共用反而比較好」。
- **事前預測：**
  1. T 在所有寬度、所有 N 都到 95% 以上（天花板）。
  2. S 的正確率隨 N 變大而下降；跌破 50% 的 N 隨寬度（也就是 m）變大。
  3. S 和 P 判定「沒有差別」：這個任務用不到 FFN 那半，共用位址不該有影響。
- **本機檢查時發現並修正的（不是結果）：** 在 Mac mini CPU 上用詞表 128、N＝4 和 8 的小設定檢查時，第一版在每個問題後面
  放了答案。T 因此學會一條捷徑：從前文還沒被答過的值裡挑，正確率剛好是 H(N)/N（N＝4 是 52%，N＝8 是 34%），
  怎麼調學習率、weight decay、寬度都卡在這裡。改成標準格式（不放答案）後，T 在 3e-4、1e-3、3e-3 都到 100%，S 也是。
  第一版的試點 Job（c1638ee）在任何 run 開始前就撤掉了，沒有結果。

### 試點結果和修正（2026-11-07，試點之後、掃描之前）

試點（`mem_pilot`，d＝128、序列 512、N 到 128、40K 步）的測試正確率：
- S（lr 1e-3）：2K 步就到 98% 以上，最後每個 N 都是 100%。
- P（lr 1e-3）：10K 步到 100%。
- T：lr 1e-3 在 2K 到 10K 步之間學會，最後 100%；lr 3e-4 在 10K 到 20K 步之間學會，40K 步時 99.1–99.9%；
  lr 3e-3 到 20K 步都還停在亂猜（約 1/N），20K 到 30K 步之間學會，40K 步時 99.98–100%。
- 訓練時間（A6000，0.5–0.6 核 CPU）：S 2312 秒、P 2772 秒、T 958–1142 秒。

套用規則：
- T 學得會（lr 1e-3 在 N≤32 都 100%），天花板成立，可以掃描。
- T lr 3e-4 在 20K 步的平均正確率是 97.2%，40K 步是 99.7%，差超過 1 個百分點，所以 M1 用 **40K 步**。

**修正（Gary 2026-11-07 核准）：** 三個模型在 d＝128 都到 100%，比不出差別。原因是設計漏洞：N 最大 128，
但槽數 m 是 171–651，比 N 還多，預測 2 說 N 接近 m 才會掉，所以原設計測不到容量上限。改成：
- 寬度 d ＝ 32、64、128（m ＝ 83、171、323），N 加上 256，序列 1024，batch 64。
- 其他規則（學習率範圍、選法、3 個 seed、判定標準、預測）不變。預測 1 和 2 改成對新範圍成立：
  T 在新範圍仍到 95% 以上；S 在 N 超過 m 之後明顯下降，d＝32（m＝83）最早掉。
- 掃描計畫：`scripts/nrp/mem_m1.txt`（36 行，`analyze.py plan 40000` 產生）。

## 8. M2、M3 的規則（2026-11-07，在任何 M2、M3 結果之前寫下）

Gary 核准做 M2、M3，用互動 pod。照 PoC 規則：每組 1 次、lr 1e-3、seed 1337、40K 步，不掃描、不加 seed。

## 12. 查統一版在隔 1024 崩掉的原因（2026-11-07，在任何診斷結果之前寫下）

Gary 要先查第 11 節裡統一版（S）在干擾版距離測驗、隔 1024 時掉到 0% 的原因（分開版 P-free 還有 97%）。

**讀出公式（`model.py` UnifiedBlock）：** 每個格子 a 有先驗量 w_a 和前文寫入量 E_a（衰減累加的寫入位址）。
S 的讀出是 y = μ(r·w/(w+E)) + N·r/(w+E)：固定知識那半乘上 w/(w+E)，前文寫得越多就越小。
P-free 的固定知識讀出 μ(r_s) 不乘這個比例，前文記憶有自己的位址和格子。每層只有一個遺忘率 λ。

**三個假設：**
- H1 固定知識被壓掉：干擾雜訊是鑰匙和值，必須寫入，寫滿所有格子後 E 很大，S 的固定知識那半被壓掉，
  整個網路失效，不只是記憶。
- H2 前文記憶被稀釋：被問鑰匙所在的格子被雜訊寫入蓋掉。P-free 的前文格子一樣多卻撐住，所以要成立得是 S 的位址比較不挑。
- H3 遺忘太快：S 學到比較短的記憶時間常數，隔 1024 時原本的鑰匙值已經忘光。

**做法：**
1. 用同樣設定、同 seed 重跑 S 和 P-free 並存權重（`scripts/nrp/mem_diag.txt`，`--save=1`），先確認重現第 11 節的結果。
2. 在 Mac 上用存下的權重、逐 token 的 PyTorch 寫法（先確認跟模型原本的 forward 輸出一致）量：
   - 崩掉的位置：G＝256、384、512、640、768、896、1024 的答對率。
   - 各層學到的記憶時間常數 1/rate，S 對 P-free。
   - S 在 G＝1024 答錯時答了什麼：值、鑰匙、還是其他 token。
   - 問題位置上 S 的固定知識比例（用位址 r 加權的 w/(w+E)），G＝256 對 1024。
   - 三個只在測驗時做的介入（不重練）：A 雜訊完全不寫入；B 雜訊寫入前文記憶，但不算進壓低固定知識的 E；
     C 雜訊算進 E 去壓固定知識，但不寫入前文記憶。
- **怎麼判讀：** H1 → B 和 A 讓 S 回升、C 不會；H2 → C 和 A 回升、B 不會；H3 → A 也救不回來，而且 S 的時間常數明顯比 P-free 短。
  可能不只一個原因，結果照實寫。
